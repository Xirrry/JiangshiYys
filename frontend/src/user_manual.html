适用版本：v9.48（设备实验版）｜Windows 64 位便携正式版｜2026-11-10

本工具用于保存角色登录环境、组合启动方案、排列游戏窗口，并为角色绑定代理。游戏登录、账号确认及验证码仍由用户在游戏中完成。它不包含游戏本体，也不提供游戏账号或代理线路。

1. 安装与第一次启动

返回目录 ↑
  1. 将发布 ZIP 完整解压到可写目录，例如 D:\Tools\YysLauncher。不要直接在压缩包里运行。
  2. 双击文件夹中的 僵尸痒痒鼠.exe。便携包已经包含 Python，普通使用不需要安装 Python、Node.js 或开发工具。
  3. 电脑需有 Windows 64 位系统、Microsoft Edge WebView2 Runtime，以及已能正常运行的新版阴阳师桌面客户端。建议使用 Windows 10/11；其他系统未验证。
  4. 若提示缺少 WebView2，请安装微软官方 WebView2 Evergreen Runtime，再重新启动。安装入口见软件包的 运行环境说明.md。
  5. 软件启动时会检查游戏目录：已有有效配置会保留；路径失效且只检测到一个安装目录时自动保存。若检测到多个目录或没有找到，在侧栏「游戏目录」点击「自动检测游戏目录」选择结果，也可手动浏览，最后点击保存并识别。例如选择 D:\Game\yys，而不是 Documents、缓存目录。
  6. 首次使用先添加并确认一个角色，再创建启动方案。建议先验证单角色能正常进入庭院。

同一份启动器目录同时只打开一个界面。不要将软件放到需要额外写权限的系统目录。移动软件前先关闭本工具启动的游戏；游戏资源通过目录链接共享，移动游戏安装目录后需重新配置和核对链接。

2. 三个主要入口

返回目录 ↑
入口用途
启动方案保存角色组合、成员顺序、窗口尺寸、位置、启动间隔及方案游戏设置
角色管理添加角色、确认身份、搜索、备注、分组、单角色启动、代理绑定、删除与恢复
代理管理管理 SOCKS5、检测连接、切换内置 TCP 或老鱼专业版执行方式

「角色」保存身份和登录缓存；「方案」保存这些角色的引用及启动配置。同一个角色可以加入多个方案，缓存共用一份，方案中的窗口和游戏设置可以分别保存。将角色移出方案不会删除角色。

3. 添加一个新角色

返回目录 ↑
  1. 进入「角色管理」，点击右上角「添加角色」。按提示配置游戏目录后，会打开一个独立游戏窗口。
  2. 在这个窗口中自行登录账号、选择目标区服和角色，进入庭院。
  3. 等待启动器读取本次登录产生的角色记录。若没有自动出现确认框，选中该角色，点击底部「读取角色信息」。
  4. 核对确认框中的昵称和区服，点击「信息正确，保存角色」。如果不对，取消确认，回游戏切换到正确角色后再读取。
  5. 保存后，下次使用该角色的「启动」按钮即可复用独立登录缓存。登录态过期、账号安全确认或游戏要求验证时，仍需要手动处理。

读取依赖这个独立窗口本次写入的配置记录。刚进入庭院时可能需要稍等；如果游戏尚未保存记录，启动器会提示重试，不使用旧历史记录猜测角色。相同角色身份不能重复保存为多个条目。

4. 从平安志同步

返回目录 ↑

在「角色管理」右上角点击「从平安志同步」。默认来源是当前 Windows 用户的 %APPDATA%\com.yys.analysis\desktop-accounts，也可选择其他有效的平安志账号目录。

  1. 先退出要同步角色对应的游戏窗口，避免来源数据正在写入。
  2. 刷新列表，勾选需要的账号条目。
  3. 点击「同步所选账号」，等待每条结果。只同步勾选条目的登录缓存，不修改平安志来源。
  4. 回到角色管理，检查昵称、区服和状态。来源失效或需要重新绑定时，按提示在独立窗口重新登录并确认。

本版本不提供从原游戏全局缓存导入的入口。账号登录凭证可能包含同一网易账号下的多角色权限；保存一个角色条目不等于把凭证限制为只能登录这个角色。游戏资源仍通过共享方式使用，不为每个角色完整复制游戏。

重复同步用于更新已有来源；先退出目标角色再操作。重新同步会保留已有角色的备注、分组、代理绑定和角色游戏设置。不要在同步、启动或游戏运行期间手动改写缓存。

5. 角色管理、分组与视图

返回目录 ↑

角色管理提供「卡片」「列表」「表格」三种视图，可按使用习惯切换。搜索支持昵称、区服及备注；状态筛选包括已就绪、运行中、待登录确认、需重新绑定等。

  • 单击条目可选中角色；复选框用于批量操作，两者用途不同。
  • 单角色「启动」使用默认 960 × 540 窗口和角色游戏设置；角色已运行时会定位现有窗口，不再开一份。
  • 点击「⋯」打开固定弹窗管理备注、分组、代理及角色游戏设置。修改后保存。
  • 点击「新建分组」创建分类；拖动角色到目标分组或拖动时出现的分组标签，可移动分组归属。
  • 「全选当前」只选择当前筛选结果；执行批量绑定或删除前核对已选数量。
  • 分组用于整理角色，不等同于启动方案。需要确定启动顺序时，在方案成员中排序。

删除和恢复角色

先退出角色游戏，再使用管理弹窗的删除入口或「删除所选」。删除会将角色从所有启动方案移出，但保留本地登录缓存和已移除记录。可以在「已移除」中恢复，恢复后需要自行重新加入方案。

删除角色不会释放缓存占用，也不会删除平安志来源。本版不提供批量清空账号目录的功能。

「已移除」中的「永久删除并清理」会统计该角色的私有文件大小、文件数和目录路径。核对昵称、区服和路径后点击「确认删除并清理缓存」，将真正删除这个角色的私有登录缓存及记录，释放其占用空间。每次只处理一个角色，不能从软件恢复，需要重新添加并登录。共享游戏资源、平安志来源和历史配置备份保留；资源目录链接只移除链接本身，不进入目标目录。正在运行、已经恢复、确认过期或缓存内容发生变化时拒绝执行，需重新检查。中途遇到权限或占用错误会保留角色记录，并明确提示可能已部分清理；关闭相关程序后可重新统计。

6. 创建、保存和排序启动方案

返回目录 ↑
  1. 进入「启动方案」，在左侧「方案列表」点击「新建」。
  2. 输入方案名称，点击「＋ 角色」，勾选成员并确认。
  3. 拖动成员调整启动顺序。成员区域支持列表、卡片、表格三种视图。
  4. 在右侧「方案配置」设置屏幕、尺寸、排列方式、启动间隔及游戏设置。
  5. 点击方案名称旁的「保存」。看到「已保存」后，组合及设置已写入本地。

方案列表本身也可以拖动排序。方案及成员支持聚焦后按 Alt + ↑ / ↓ 调整顺序；成员顺序修改后需保存方案。

「移出」只移出当前方案；「删除方案」只删除组合配置，不删除角色或缓存。同一角色可出现在多个方案中，但同时共用一个已跟踪游戏实例，不会因切换方案产生独立的第二份角色进程。

「未保存」表示当前正在编辑草稿。启动当前组合会使用当前草稿；如果要下次保留，务必保存。关闭启动器时有未保存方案会提示保存或放弃。

7. 启动、启动队列与关闭

返回目录 ↑

点击顶部「启动当前组合」按当前成员顺序提交启动。右侧「启动间隔」默认 0 秒，可设为 0～300 秒，用于相邻角色启动请求之间的等待。它不等于等待前一个角色登录成功后才继续。

启动队列中可查看「待提交」「正在提交」「准备窗口」「已就绪」「失败」「已取消」「需登录绑定」。窗口就绪不代表已经自动完成账号验证或进入庭院。

  • 「停止后续启动」取消尚未提交的角色，已提交或已打开的游戏继续运行。
  • 「仅重试失败项」只重新处理本轮失败成员，保留本轮启动时的尺寸、成员顺序、排列位置和游戏设置。
  • 「清除记录」仅清理本轮队列显示，不关闭游戏。队列只保留在当前启动器会话中。
  • 未确认角色应先单独登录并确认，再加入批量启动组合。
  • 方案成员的「启动」只启动这一个角色，使用当前方案的窗口配置和游戏设置。

关闭窗口的范围

方案成员的「关闭」只关闭该角色。顶部「关闭」菜单可关闭当前组合、符合界面条件时的已保存方案或全部由本工具跟踪的游戏。角色管理也提供关闭所选。

这些按钮直接结束已跟踪且进程创建时间匹配的游戏进程，跳过游戏内退出确认；未保存的本地设置可能丢失。它们不用于关闭其他启动器打开的无关窗口。同一角色被多个方案共用时，关闭的是同一个游戏窗口。

关闭启动器界面通常不会主动关闭已经运行的游戏。若要关游戏，请先使用相应关闭按钮。代理游戏依赖其后台控制器，测试或运行期间不要手动结束控制器进程。

8. 窗口尺寸和排列

返回目录 ↑

右侧「方案配置」中的「目标屏幕」使用显示器工作区；刷新屏幕可更新新接入或发生变化的显示器信息。工作区尺寸只是可用屏幕范围，不是单个游戏窗口尺寸。

默认单窗口为 960 × 540。勾选「锁定 16:9」时，输入宽度后自动计算高度。点击「应用尺寸」修改当前方案成员的尺寸，然后保存方案。

方式适用场景
整齐网格按列数、间距及留白将窗口排成行列
错落排列使用错落位置显示多个窗口
玩家自定义使用每个角色分别保存的坐标和尺寸

预览中点击窗口卡片可选择角色，拖动可编辑位置；「放大编辑」提供更大的操作区域。成员行「设置」可精确输入画面宽高及屏幕 X/Y 坐标。副屏坐标允许为负。

点击「一键排列」才会把布局应用到正在运行的游戏。启用「启动后自动排列」可在启动准备完成后自动应用。仅保存方案或修改预览不等于已经移动游戏。「恢复位置」用于恢复记录中的上次位置，具体可恢复数量以操作提示为准。

如果预览提示越界，减少窗口尺寸、列数、间距或留白，或改用其他屏幕。窗口太多时，软件不会把 960 × 540 自动压缩成任意小尺寸。

9. 声音、动画、画质：三级游戏设置

返回目录 ↑

游戏设置在新游戏进程创建前写入角色私有配置，已运行窗口需退出后重新启动才生效。

优先级按每一项独立计算：当前方案覆盖 → 角色覆盖 → 全局默认。

位置设置方法
全局默认方案配置底部「全局」按钮，保存后作为继承默认
角色设置角色管理「⋯」弹窗，每项选择继承全局、强制或不强制，保存角色
方案设置方案配置「方案游戏设置 → 修改」，应用到方案后再点击方案「保存」

三项功能分别为：关闭音乐、音效、视频、语音且四项音量归零；关闭游戏支持的登录动画选项；本地已知画质项最低、30 帧、最低渲染档位并关闭抗锯齿。新配置的全局默认三项均启用。

「继承」使用上一级值。「不强制，保留游戏设置」会覆盖上级强制要求，但不会自动恢复以前的音量、动画或画质。如果要恢复正常画质和声音，先取消对应强制项，再进入游戏自行调整。

角色管理的单独启动使用角色和全局；方案启动及方案内成员单独启动会再叠加方案设置。首次修改私有配置会保留 clientconfig.before-launch-settings。原游戏安装目录配置不被这些设置覆盖。

本功能使用本地已知配置项，不保证关闭天气等账号侧特效，也不会删除音视频资源。遇到不支持的游戏配置版本会提示失败，应先确认客户端版本和错误信息。

10. 代理管理与角色绑定

返回目录 ↑

使用警告：IP 代理功能未经完整测试，不保证可行性、兼容性或稳定性。检测通过不代表游戏所有流量均已代理，可能出现连接失败、掉线或客户端异常，请谨慎使用。

不使用代理时，将角色代理设为「直连」即可。代理绑定属于角色，同一角色在所有方案中共用该绑定；不是按方案分配不同代理。

添加 SOCKS5

  1. 左侧打开「代理管理」，点击「添加 SOCKS5」。
  2. 填写名称、主机、端口及必要的认证信息。主机不包含 socks5:// 前缀。
  3. 保存代理，再进行连接检测。编辑认证字段留空会保留原有已保存凭证；勾选清除认证才删除它。
  4. 到角色管理「⋯」选择代理并保存，或勾选多个角色后点击「绑定代理」。
  5. 使用原有角色或方案启动按钮。绑定代理的角色准备失败时会报错，不自动改成直连启动。

代理认证使用 Windows 当前用户的数据保护机制在本机加密保存。不要把密码发到错误反馈中。更换电脑或 Windows 用户后，旧加密认证可能无法解密，需要重新填写。

内置 TCP 模式

选择「内置 TCP」并保存执行方式。同时只支持 1 个绑定代理角色；其他未绑定角色可以直连。启动过程中需要用户完成 Windows 管理员授权。

当前范围为托管进程组的 IPv4 TCP；UDP、IPv6 不提供代理转发，DNS 自动接管未启用。界面中的连接计数表示观察到的转发记录，不代表全部流量、所有玩法或系统 DNS 已验证。需要完整 UDP/DNS 能力时，应核对外部代理软件的实际能力和设置。

老鱼专业版模式

  1. 自行安装并启动老鱼专业版，启用其本机 API。
  2. 在本工具代理管理选择「老鱼专业版 · 本机 API」，填写端口；默认 22999。
  3. 点击「检测老鱼连接」，成功后保存执行方式。
  4. 点击「刷新老鱼线路」，现有 SOCKS5 线路会出现在本工具列表及角色绑定选项中。
  5. 为角色绑定线路并正常启动。启动器会同步或复用线路，确认游戏 PID 的线路绑定后再恢复游戏执行。

老鱼导入线路的地址、认证、启停由老鱼维护；本工具可修改本地显示名。老鱼中移除或停用的线路会体现为不可用状态。手动添加的代理也可以通过「同步此代理到老鱼」复用或创建线路。

老鱼模式支持为多个角色分别绑定线路，DNS、UDP 及故障处理能力由老鱼自身设置决定。本版本已完成本地 API 和模拟流程检查；不把这些检查等同于目标电脑的真实游戏出口验证。老鱼免费版没有接入。

检测结果怎样理解

提示含义
TCP 通过已保存代理能够建立本次 TCP 测试连接
出口 IP 未取得出口查询目标可能被拒绝，需结合 TCP 结果判断
UDP 协商通过代理接受了 UDP 协商，不等于 UDP 数据能往返
UDP 数据往返通过指定测试目标的数据往返成功，不等于全部游戏 UDP 已接管
DNS 代理通道通过测试解析通道可用，不代表游戏 DNS 自动接管已启用
老鱼 PID 线路已确认老鱼 API 记录中的进程与线路匹配，不等于完整出口验证

展开「连接检测与诊断」及运行条目的「连接详情」可以查看细节。不要仅凭 ping 值或一条转发计数认定所有游戏流量都已代理。

更换、解除与删除代理

先关闭对应角色，再修改绑定。选择「直连」即解除绑定；解除或更换后，旧代理失败提示会清除。正在运行的角色禁止直接换绑。

删除测试代理前，先解除所有引用角色的绑定，并结束使用它的代理会话。删除只移除本工具本地条目，不会删除老鱼中的线路。已移除的老鱼条目不会在下次刷新时自动重新出现；需要时点击「恢复已移除线路」再刷新。

11. 数据位置、空间、备份与升级

便携包运行数据位于解压目录的 data 下。界面设置和游戏运行会继续产生文件，请保留可用空间。

路径内容

data/profiles/按角色 ID 映射的私有登录环境、游戏本地配置和缓存
data/proxies.json代理条目、老鱼关联及本机加密认证

共享游戏资源减少重复占用；账号私有缓存、游戏临时下载及备份仍会增长。平安志原账号目录在 Windows 用户的 Roaming 下，它的占用不会因同步到本工具自动减少。

备份和迁移

  1. 退出所有由本工具启动的游戏，再关闭启动器及代理会话。
  2. 备份整个 data 文件夹；保留游戏原始安装目录。账号目录可能包含指向游戏资源的目录链接，备份工具应保留链接，不要沿链接重复复制整套游戏。
  3. 更新时将新版解压到新目录，保留旧版本；确认没有运行中的角色后再迁移 data。不要用空配置覆盖旧 data。
  4. 在同一 Windows 用户、同一游戏路径下迁移最直接。换电脑、换系统用户或换游戏路径后，应重新配置目录、代理认证，必要时重新登录或重新同步角色，不保证直接复制全部目录即可工作。
  5. 启动新版本后先核对角色、方案和代理，再测试一个角色。

不要将运行后的整份便携目录直接发送给他人：里面可能包含账号登录缓存和代理认证。对外分发应使用不带 data 的干净发布包。

12. 常见问题

返回目录 ↑

软件没有打开或只出现空白窗口

确认 ZIP 已完整解压、目录可写、WebView2 已安装，并且没有打开同目录的另一个启动器。查看 desktop-error.log。不要只复制一个 EXE、BAT 或 HTML，程序需要整个目录结构。

找不到游戏或提示下载资源

重新选择已经安装完整的游戏根目录，确认原游戏可以正常启动并完成必要更新。新角色会创建私有登录环境，但仍依赖原游戏共享资源。游戏路径变化或资源链接异常时，先退出角色再排查，不要删除共享游戏资源来“清理缓存”。

昵称或区服没有读取出来

确认是在本工具为该角色打开的窗口中进入庭院，等待游戏保存记录后再点击「读取角色信息」。如果登录错角色，切换正确角色；角色身份不匹配时不能强行确认。区服资料可能随游戏更新变化，反馈时提供错误文字及区服名即可。

点击启动没有再开第二个窗口

角色可能已在运行，启动器会定位已有窗口。同一个角色在多个方案中共用实例。如需不同角色独立运行，应分别添加和确认不同角色。

修改尺寸、声音或画质没有马上生效

尺寸修改后先应用并保存方案，再点击一键排列；游戏设置只在下次新启动时生效。已运行角色仅定位窗口，不会重新套用另一方案的游戏设置。

老鱼 API 无法读取

检查老鱼专业版是否启动、本机 API 是否启用、端口是否一致。先点击检测，再检查线路是否启用及角色绑定是否仍有效。关闭游戏后解除绑定可改为直连，旧错误提示会消失。

无法删除代理或修改绑定

检查是否仍有角色绑定或后台代理会话在运行。先关闭角色并等待清理完成，再解除绑定，最后删除代理条目。

关闭方案影响了另一个方案中的角色

两个方案引用同一角色时，共用同一游戏实例。方案只是组合引用；关闭其中任一处的角色都会关闭该实例。

删除了角色但空间没有下降

删除是保留缓存的可恢复移除。到「已移除」可恢复角色。如需释放空间，进入「已移除」，逐个选择「永久删除并清理」，核对私有目录与统计大小后确认。共享游戏目录和平安志来源的占用不会因此减少。

本工具不自动完成账号验证，不保证登录凭证永久有效。游戏升级、配置格式变化、系统权限及第三方代理变化都可能影响兼容性。本地资源隔离不等于虚拟机或系统安全隔离，也不改变游戏服务自身的账号规则。

反馈时附软件版本、操作步骤、错误文字或已遮盖敏感信息的截图；说明是直连、内置 TCP 还是老鱼模式。不要公开账号缓存、完整代理认证、accounts.json 或 proxies.json。不同电脑的系统环境可能不同；迁移后应先验证首次启动，再测试一个角色和代理绑定。

实验性设备接口隔离

使用警告：设备接口隔离功能未经完整测试，不保证可行性、兼容性或稳定性，也不保证形成独立硬件身份。可能出现登录异常或客户端退出，请谨慎使用。

角色管理「⋯ → 设备接口隔离 · 实验性」中，退出角色后生成独立参数，再勾选「下次启动启用实验」并保存。默认关闭；参数按角色保存，同一角色在各方案共用，重新同步时保留。已运行窗口不能更换参数，重复启动只定位原窗口。

本功能在窗口就绪后加载组件，仅覆盖 GetComputerNameW、GetVolumeInformationW、GetAdaptersInfo、GetAdaptersAddresses。MAC 为基值，各网卡按索引派生对应地址；不改变系统真实网卡、磁盘或注册表。初始化失败会关闭该角色，不显示为已就绪。

本地双自有进程的独立性和恢复已验证；指定测试角色先通过实验控制器测试，再从保存的角色配置经常规启动入口重启，两次都由用户确认进入庭院且运行正常，并观察到四类接口调用。代理组合与多个设备实验角色并发尚未实机验证。这不代表覆盖启动早期查询、MachineGuid、主板/固件、WMI、SDK 缓存标识或所有子进程，也不能保证服务端将角色识别为不同物理设备。客户端更新后可能不兼容。

设备实验状态核验

角色管理弹窗会区分「已配置，待下次启动」「本次启动已加载，尚未核验」和「当前窗口未核验」。运行中的角色可点击「检查当前窗口」，读取一次组件状态与四类接口调用计数，并显示核验时间。结果为当时快照，不能代表完整身份覆盖或持续监控。

从别的启动器会话启动的窗口，没有本次加载记录时会显示未核验；不会盲目重复加载组件。窗口退出后会回收本启动器持有的实验句柄，旧核验结果不应用于新窗口。重新生成参数需要确认，保存前可取消。

虚拟机对照测试

虚拟机提供独立操作系统及虚拟设备，但不保证游戏兼容，也不代表不可被识别为虚拟环境。可先用一个 Windows 来宾系统进行低画质、30帧的单角色测试。为便于区分问题，第一轮保持设备接口实验关闭。

本工具不直接创建或管理虚拟机。来宾系统中的游戏 PID 不属于宿主机；现有代理按进程绑定与本机 API 需要在相应系统中重新核对，不能直接套用宿主机 PID。虚拟系统、游戏、快照及临时文件都需要存储空间，建议使用有充足余量的非系统盘。
